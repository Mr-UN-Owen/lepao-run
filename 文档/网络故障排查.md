# 网络故障排查：开脚本后上不了网 / 小程序报「网络接口错误」

> 适用版本：v2.3 起（PAC 模式 + 看门狗）。旧版本的同类问题也按本文修，第 1、2 步通用。

## 一、先按顺序动手，三步之内基本都能好

| 顺序 | 双击 | 作用 |
|---|---|---|
| 1 | `启动脚本/6-一键修复网络.bat` | 按 `proxy_backup.json` 还原原代理 → 关掉指向本机的代理 → 删残留 PAC → 重置 WinHTTP → 清 DNS |
| 2 | `启动脚本/0-首次使用-安装证书.bat`（弹「安全警告」点 **是**） | 把本机根 CA 装进「当前用户 → 受信任的根证书颁发机构」 |
| 3 | `启动脚本/5-环境自检.bat` | 检查 Python / 库 / 证书 / openssl / 端口 / 代理 / PAC |

自检里这三行必须是 OK：

```
[OK] 根证书已装入当前用户受信任根
[OK] 固定代理：ProxyEnable=0 ProxyServer=(空)
[OK] PAC：空（正常）
```

有 `[X]` 或 `[!]` 就照它后面那句话做。

## 二、两个真正的成因

### 1. 根证书没受信 → 所有 HTTPS 握手中断

抓包是**中间人**：MITM 用自己签的叶证书冒充 `api3.lptiyu.com`、`www.baidu.com`……
客户端只认「受信任的根证书颁发机构」里的根 CA。根 CA 没装（或被安全软件清了），
每一次握手都会在 TLS 阶段被拒，客户端看到的就是

- 浏览器：`ERR_CONNECTION_CLOSED` / `你的连接不是私密连接`
- 微信小程序：**网络接口错误**（底层 `wx.request:fail`，errno 通常 1005/600001）

**只要代理指向 MITM，而 MITM 的证书不被信任，就没有一个 HTTPS 能通。**
这不是"网坏了"，是"所有网站都在报证书错误"。

判断方法（不需要装任何东西）：

```powershell
certutil -user -store Root | findstr /i lepao
```

有 `lepao-debug-ca` = 已装；没有就双击 0 号脚本。

### 2. 系统代理指向死端口 → 整机断网

旧版抓包会把系统代理写成 `127.0.0.1:8086`（全局）。只要 MITM 这个进程没了
（关窗口、崩溃、被安全软件杀、端口被占），代理设置却还留着 → 浏览器、微信、更新程序
全部把请求发到一个没人监听的端口 → **看起来就是"网断了"**。

更隐蔽的一层：旧版 `1-启动网页控制台.bat` / `2-启动网页-局域网模式.bat` 里直接
`reg add ... ProxyEnable /d 0`，会把你自己的 **Clash / v2ray / 公司代理一起关掉**。
于是"开了个脚本，别的网页全打不开"，而脚本本身的页面是好的。

## 三、现在的机制（v2.3）

| 项 | 行为 |
|---|---|
| 默认代理范围 | **PAC**：只有 `*.lptiyu.com`、`*.weixin.qq.com`、`*.servicewechat.com` 走 `127.0.0.1:8086`，其他全部 `DIRECT` |
| PAC 托管 | 控制台在 `http://127.0.0.1:8780/proxy.pac`；命令行抓包时启动器自己在 `127.0.0.1:8091` 起一个 |
| 兜底 | PAC 里写的是 `PROXY 127.0.0.1:8086; DIRECT`，MITM 挂了也只是抓不到包，网页照开 |
| 看门狗 | 每 1.2 s 检查 MITM 进程与端口，连续 3 次不通就还原代理并提示 |
| 退出还原 | 四项全还原：`ProxyEnable / ProxyServer / ProxyOverride / AutoConfigURL`，并清掉 `proxy_backup.json` |
| 启动清理 | 只清「指向本机 8081/8086/8090」的残留 + 指向本机的 PAC，**不动**你自己的代理 |
| 兼容模式 | 少数客户端不读 PAC → 网页点「兼容模式（全局代理）」，或 `python 工具\capture_launcher.py --global`（仍排除本机与局域网） |

## 四、抓不到包，但网络正常

| 现象 | 原因 | 处理 |
|---|---|---|
| 代理已设、日志没动静 | 小程序走 UDP/QUIC 或忽略系统代理 | 用兼容模式；微信完全退出后重开（`WeChatAppEx.exe` 也要退） |
| 日志只有 502 | 上游连不上（本机 DNS/网络问题） | `nslookup api3.lptiyu.com`，确认能出网 |
| `[TLS] 域名 握手失败（CA 未受信？）` | 证书没装 / 装到了别的用户 | 0 号脚本，注意弹窗点【是】 |
| `端口 8086 被占用` | 上一个 MITM 没退 | 6 号脚本 → 任务管理器结束 `python.exe` |
| `找不到 openssl` | PATH 里没有 | 装 Git for Windows，或把 `openssl.exe` 目录加进 PATH |

## 五、手动兜底（脚本也失效时）

1. `Win+R` → `inetcpl.cpl` → 「连接」→「局域网设置」→ 取消勾选「为 LAN 使用代理服务器」
2. 同一窗口点「高级」，把「自动配置脚本」清空
3. Windows 设置 → 网络和 Internet → 代理 → 「自动检测设置」关、「使用代理服务器」关
4. 命令行补两刀：

```bat
netsh winhttp reset proxy
ipconfig /flushdns
```

5. 还不行就禁用再启用一次网络适配器（设置 → 网络 → 更改适配器选项）。

## 六、别做的事

- 别在抓包进行中用任务管理器强杀 `python.exe`：代理会留在死端口。真要强杀，杀完立刻跑 6 号脚本。
- 别把 `程序/_private/mitm_ca/` 发给别人：那是本机私钥。
- 别把系统代理手动设成 `127.0.0.1:8086` 然后忘了关——6 号脚本会帮你收尾。

# 附：提交一直卡在「提交中…」

这是和上面「断网」完全不同的一类问题，单独说清楚。

## 一、为什么界面会一直停在「提交中」

不是"提交很慢"，而是**失败被吞掉了**。三处代码叠在一起：

| 位置 | 老行为 |
|---|---|
| 前端 `api()` | `fetch` 没有超时、没有 `try/catch` |
| 前端 `doSubmit()` | 写下「提交中…」之后，只有成功和"后端返回 ok:false"两条路；一旦 `fetch` 抛异常，这行字再也不会被改写 |
| 后端 `/api/submit` | 170 行没有整体 `try/except`；任何异常都让 `BaseHTTPRequestHandler` **直接关连接、不发响应** |

后端断连接 → 浏览器拿到 `net::ERR_EMPTY_RESPONSE` → `fetch` reject → 前端没人接 → 永久「提交中…」。

所以"一直提交中"其实包含两种完全不同的情况：**真的在等**（DNS 卡死、链路拥塞）和 **几秒就失败了但没人告诉你**（被 RST、证书/协议错误、后端异常）。

## 二、一次提交要串 6~8 次外网请求

`/api/submit` 的实际顺序（全部串行）：

| 步 | 请求 | 超时 |
|---|---|---|
| 1 | `Run2/beforeRunV260`（查今天有效次数） | 20 s |
| 2 | `Run2/beforeRunV260`（刷新服务端上下文） | 20 s |
| 3 | `Run/getTimestampV278` | 20 s |
| 4 | `WpIndex/getOssSts` | 20 s |
| 5 | **上传轨迹到阿里云 OSS** | **40 s** |
| 6 | `Run2/beforeRunV260`（stop 前必调） | 20 s |
| 7 | `Run/stopRunV278`（真正落库） | 20 s |
| 8 | `Run/recordDetailV270`（复核） | 20 s |

最坏 160 s 以上。其中第 5 步走的是 `lptiyu-data.oss-cn-hangzhou.aliyuncs.com`，**和 API 不同域、不同出口策略**，也是最容易被校园网/宿舍网限速或阻断的一步。

## 三、校园网下的四种典型失败

| 现象 | 原因 | 判据 |
|---|---|---|
| 一开始就卡，连"今天次数"都不出来 | Portal 未认证 / 掉线，HTTPS 被劫持成认证页 | 浏览器开任意网站被跳到认证页 |
| **无限**卡住，控制台没有任何报错 | 校内 DNS 卡死（`getaddrinfo` 不受 `timeout` 约束） | `nslookup api3.lptiyu.com` 也卡 |
| 前面几步正常，卡在"上传轨迹" | OSS 被限速/阻断，晚间高峰尤甚 | 页面数据能刷新、只有提交卡 |
| 换台电脑就好了 | token 单会话被顶号 / 系统时间偏差 | 小程序里重新登录过 |

## 四、现在的机制（v2.4）

1. **前端**：`api()` 统一加 `AbortController` 超时（提交 180 s、其它 30 s）与 `try/catch`；`doSubmit()` 期间禁用按钮、每秒更新「提交中…（12s）」，`finally` 里一定复位。
2. **后端**：`do_GET/do_POST` 外面包一层，任何未捕获异常都变成 `{"ok":false,"error":...,"stage":...,"elapsed":...}` 的 JSON —— 不会再出现"静默断连"。
3. **阶段可见**：`/api/submit` 每进入一步都写 `SUBMIT_STAGE`，失败时前端直接显示"阶段：upload，已耗时 41.2s"，并提示"这一步之前轨迹可能已上传成功，先去记录列表确认再重试"。
4. **DNS 超时守卫**：`lplib.resolve_host()` 在线程里跑 `getaddrinfo`，8 s 不返回就判失败并给出人话原因，彻底消灭"无限挂起"。
5. **OSS 上传重试**：网络异常自动重试 1 次（间隔 1 s），校园网首次握手被掐的情况大多能救回来。
6. **网络自检按钮**：网页上「网络自检」→ `GET /api/netcheck`，一次测三件事：

```
乐跑 API      api3.lptiyu.com                        通/不通  TCP 0.06s
OSS 轨迹上传   lptiyu-data.oss-cn-hangzhou.aliyuncs.com  通/不通  TCP 0.02s
外网基线       www.baidu.com                          通/不通  TCP 0.04s
+ 一句结论（该换热点 / 该避开高峰 / 该查 token）
```

## 五、提交前的固定动作（30 秒）

1. 点「网络自检」，三项都要"通"；
2. `OSS 轨迹上传` 的 TCP 时间 > 2 s 就换到热点或避开 20:00–23:00；
3. 只点一次「提交」，等它自己出结果（最长 3 分钟）；
4. 如果提示"卡在 stop / review 阶段"，**先去「本学期记录」看有没有新记录**，再决定是否重试——接口没有幂等键，重复提交会多留一条无效记录。
