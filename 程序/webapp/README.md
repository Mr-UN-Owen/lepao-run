# webapp —— 乐跑网页控制台（可登录）

> 许可证同主仓库 **LRL-1.0**：仅供学习 · 不可牟利 · 再发布须署名引用
> <https://github.com/dan-cun/lepao3> 并保留全部声明。

对标 `bupt.run` 那类「填凭证就登进去看数据」的网页，逻辑全部走本仓库自己的 v3 协议实现，
零第三方服务、零外部依赖（Python 标准库 + `lepao.crypto`）。

## 启动

```bash
python webapp/server.py --port 8780
# 或双击 启动网页.bat
# 浏览器打开 http://127.0.0.1:8780
```

## 登录

网页只有一个登录框，要四个值：

| 字段 | 说明 |
|---|---|
| host | `api3.lptiyu.com`（公大实际用的是 api3，不是 api2） |
| school_id | `816` = 中国人民公安大学 |
| uid | 小程序登录后下发的用户 id |
| token | 同一批请求里的 token 串 |

这四个值从「抓一次」（`工具\抓一次.cmd`）的输出里直接抄：

```
  ★ v3 明文  api3.lptiyu.com/v3/api.php/WpIndex/index
      school_id    = 816
      uid          = UID_PLACEHOLDER
      token        = TOKEN_PLACEHOLDER
```

### 一键获取（不用记也不用抄）

登录框下面有个「**一键获取凭证（自动抓包）**」按钮，行为是：

1. 起本地 MITM（先探端口，确认监听后才动系统代理）
2. 把 Windows 代理指到 `127.0.0.1:8086`
3. 提示你打开小程序（建议先完全退出微信再重开）
4. 后台盯抓包日志，一出现带 token 的 v3 明文 → 自动保存会话 → **自动登录**
5. 无论成功、超时（240 秒）还是你手动停止，都会**恢复原来的代理设置**并结束 MITM

> 前提是进程有权限改注册表（`HKCU`）。权限不足时会明确报「改不了系统代理」，
> 并且不会留下半截状态——MITM 会被杀掉，代理一个字都不动。

### 关于「账号密码登录」

`api3` 上确实有那套 H5 页面应用（`/bdlp_h5_fitness_test/public/index.php/index/Login/`，
getToken 与验证码都活着），可以用学号+密码+验证码登录。但它拿到的是 **PHPSESSID**，
只能查成绩/报表，**不能提交 v3 轨迹**（v3 要 token）。

所以：**要提交必须用 token**，账号密码那条路只能用来"看数据"。

> token 是**单会话消耗品**：小程序重新登录会顶掉旧的，网页这边就要换新的。
> 会话会存到 `_private/webapp_session.json`（已 gitignore），下次打开网页自动恢复。

## 登录后能看到什么

- 学校 / 学期 / 本学期里程 / 有效次数 / 打卡点数 / 时间窗
- 跑区列表（公大：木樨地、团河）
- **打卡点坐标**（服务端 `run_line_info.point_list` 明文下发）
- 反作弊开关全貌（公大实测全关，只有时间窗开着）
- 本学期跑步记录列表
- 轨迹预览：随机选 2 个打卡点 → 合成环线 → canvas 画出 → 校验是否覆盖

## 轨迹逼真化参数（对照 LePaoRunner）

轨迹不是"画个圈标个距离"，而是按**真人行为模型**生成的。参数体系参考
[LePaoRunner](https://github.com/zgbjhk/LePaoRunner)（模拟器注入路线）的 `run` 配置组——
它骗的是模拟器，我们骗的是服务端行为判定，**要对付的是同一套校验**。

### 核心区别：按时间采样，不是按距离采样

| | 旧实现 | 现在 |
|---|---|---|
| 采样依据 | 每 6.4 米取一个点 | **每 1 秒取一个点** |
| 点间距 | 恒定 | 随速度 1.5~3.4 m 变化 |
| 时间轴 | 距离 ÷ 配速，完美线性 | 由速度曲线积分得到 |
| 速度方差 | **0**（一眼假） | std ≈ 0.24~0.34 |

### 参数对照表

| 参数 | 本实现 | LePaoRunner | 说明 |
|---|---|---|---|
| `sample_hz` | **1.0** | `update_hz: 1.0` | 每秒一个轨迹点 |
| `speed_jitter_pct` | **6.0** | `speed_jitter_pct: 6.0` | 配速波动 ±6%，过一阶低通（0.6/0.4），模拟真实加减速惯性 |
| `gps_noise_m` | **1.2** | `gps_noise_m: 1.8` | 定位漂移；**必须远小于点间距**，否则轨迹画成锯齿 |
| `warmup_s` | **45** | `warmup_s: 45.0` | 起步 55%→100% 线性爬升 |
| `cooldown_s` | **20** | `cooldown_s: 20.0` | 收尾 100%→45% 线性回落 |
| `pause_probability` | **0.65** | `traffic_events: true` | 65% 概率插入 1~2 次停顿 |
| `pause_seconds` | **2~7** | — | 单次停顿 2~7 秒，速度归零 |
| `lap_drift_m` | **1.6** | `lap_line_drift_m: 1.6` | 每圈起跑线横向漂移，三圈一循环，轨迹不再完全重合 |
| `stride_m` | **1.15** | `cadence: 0`（自动） | 步幅，用于把速度换算成步频 |
| `cadence` | **150~190** | — | `step_info` 由逐秒速度反推，与距离/配速自洽 |
| `corner_radius_m` | **40.82**（田径场弯道） | `corner_radius_m: 6.0` | 弯道半径；本实现直接采用标准田径场几何（移植自 run.bupt.app） |

### 逼真化前后对比

| 检测点 | 逼真化前 | 逼真化后 |
|---|---|---|
| 速度标准差 | 0 | 0.24~0.34 |
| 首末速度渐变 | 无（全程匀速） | 45 s 爬升 / 20 s 回落 |
| 中途停顿 | 无 | 0~2 次，每次 2~7 s |
| 点间距 | 恒定 6.4 m | 1.5~3.4 m 浮动 |
| 每圈重合度 | 完全重合 | 横向漂移 ±1.6 m |
| 步频与速度 | 无关（纯随机） | `v×60/stride`，自洽 |
| 步幅 | 波动大 | 稳定 1.15~1.2 m |

代码位置：`lepao/realism.py`（行为模型）+ `webapp/server.py: build_run()`（几何 × 速度曲线）。

## 关于「提交」

**2026-11-24 20:39 首次提交成功**（record 147108，`status=1 / 自动确认有效`，3.05 km / 946 秒）。

### 三条硬规则（全部实测得出）

**1. 必须用跑区模式 `Run/stopRunV278`，不能用 `Run/stopFreeRunV220`**

自由跑能落库，但 `run_zone_name = "自由跑"`、`log_num` 恒为 0，不进成绩体系。

**2. 参数必须落在服务端规则表内**（`beforeRun` 的 `time_rule_arr` 明文下发）：

```json
{"start_time":"21600","end_time":"79200",        // 06:00~22:00
 "min_distance":"3.00","max_distance":"20.00",   // 3~20 km
 "min_log_num":"2","min_num":"1",                // ≥2 个打卡点，每天 ≥1 次
 "min_pace":"330","max_pace":"180",              // 配速 3'00"~5'30"
 "pace_str":"3`0``~5`30``"}
```

**3. 轨迹文件的 `d` 时间轴必须「包住」`[start_time, end_time]`**

这是最难发现的一条，也是最关键的一条。对比真机样本：

| 锚点 | 真机样本 | 修复前 | 修复后 |
|---|---|---|---|
| 首点 | `start_time*1000 + 724ms` | 正好等于 `start_time*1000` | `+100~900ms` |
| 末点 | `end_time*1000 + 244ms` | **早 1000ms**（`int()` 截断） | `+100~900ms` |

末点比 `end_time` 早 1 秒，服务端就认为轨迹没覆盖到最后时刻 → 判 **`跑步时间异常`**。
这个错误会一直掩盖后面的问题：里程、配速都合格了，只报这一条。

校验顺序：**里程 → 配速 → 时间轴**。所以配速不合格的记录会先报「速度过慢」，
只有配速合格了才会暴露时间轴问题——这也是之前一直在配速上反复撞墙的原因。

## 目录

```
webapp/
├── server.py     标准库 HTTP 服务 + 轨迹合成 + 提交组装
├── lplib.py      v3 客户端（Session: host/school_id/uid/token）
├── index.html    单页：登录 → 仪表盘 → 地图 → 预览/提交
```

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` | `{host, school_id, uid, token, student_num}` |
| GET | `/api/me` | 档案：学校/学期/跑区/打卡点/反作弊开关 |
| GET | `/api/records` | 本学期记录 |
| POST | `/api/preview` | `{distance_km, pace}` → 轨迹预览（不写服务端） |
| POST | `/api/submit` | `{confirm:true}` → 真提交（用上一次预览） |
| POST | `/api/logout` | 清会话 |
